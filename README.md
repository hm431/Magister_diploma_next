# КИС Водоканал — автоматизация задач комплекса подсистем

> Дипломная работа. Веб-приложение для аналитики и формирования проектной документации строительной компании водоснабжения. Интеграция подсистем **СРО** (сметно-расчётный отдел) и **МТР** (материально-технические ресурсы).

---

## 🎯 О проекте

Аналитический контур, который объединяет данные двух подсистем и автоматически формирует **6 типов проектных документов** на основе единого источника данных. Цель — заменить ручной расчёт графиков, заявок и отчётов на воспроизводимый алгоритмический процесс.

### Что решает

- ❌ **Было:** графики и заявки считаются вручную в Excel; данные СРО и МТР живут в разных файлах; рассинхрон приводит к простоям и дефицитам на стройке.
- ✅ **Стало:** единый веб-контур, где аналитик вводит исходные данные → получает рассчитанные графики → выгружает готовый документ в нужном формате.

## 🗂 Структура страниц

``` 
/                           Главная — описание контура и схема интеграции СРО↔МТР
/tasks                      Хаб задач — карточки, фильтр по подсистеме
/tasks/work-schedule        Задача 01 — Календарный график работ
/tasks/materials-procurement Задача 02 — График закупок МТР
/tasks/warehouse-loading    Задача 03 — Загрузка складов
/tasks/schedule-deviations  Задача 04 — Отклонение сроков по КС-6
/about                      О дипломе — метаданные ВКР, аннотация, содержание
```

Каждая страница задачи следует единому шаблону:
```
├─ форма ввода      (TaskFormMolecule)
├─ блок графиков    (TaskAnalyticsMolecule)
└─ предпросмотр документа + выгрузка (TaskDocumentMolecule)
```

Тёмная корпоративная тема, без неона. Цвет используется **функционально**, а не декоративно.

| Токен         | Значение     | Назначение                          |
|---------------|--------------|-------------------------------------|
| `--bg`        | `#0e1014`    | основная подложка                   |
| `--paper`     | `#15181d`    | карточки 1-го уровня                |
| `--paper-alt` | `#1b1f25`    | поля ввода, 2-й уровень             |
| `--line`      | `#272c34`    | рамки, разделители                  |
| `--ink`       | `#e8eaee`    | основной текст                      |
| `--ink-soft`  | `#aab1bd`    | вторичный текст                     |
| `--ink-muted` | `#6b7380`    | подписи, breadcrumbs                |
| `--accent`    | `#6a93c8`    | primary action, ссылки              |
| `--sro`       | `#7fb3b0`    | подсистема СРО                      |
| `--mtr`       | `#c9a06a`    | подсистема МТР                      |

## 🛠 Стек

- **Next.js 16** (App Router) — серверные компоненты по умолчанию, маршрутизация на основе файловой системы
- **React 19** — UI-слой
- **TypeScript** — строгая типизация
- **Tailwind CSS 4** — утилитарные стили, подключается через `@tailwindcss/postcss`
- **next/font** — оптимизированная подгрузка Inter Tight и JetBrains Mono

## 🚀 Запуск

```bash
# установка зависимостей
npm install

# dev-сервер с hot-reload (Turbopack)
npm run dev

# production-сборка
npm run build

# запуск production-сборки локально
npm run start

# линтер
npm run lint
```

После `npm run dev` приложение открывается на `http://localhost:3000`.

### Server vs Client Components

По умолчанию все компоненты в `app/` — серверные (рендерятся на сервере, не отправляют JS в браузер). Директива `"use client"` добавляется только там, где нужны хуки (`useState`, `useRouter`) или обработчики событий — преимущественно в формах ввода и интерактивных графиках.
