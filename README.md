# КИС Водоканал — автоматизация задач комплекса подсистем

> Дипломная работа. Веб-приложение для аналитики и формирования проектной документации строительной компании водоснабжения. Интеграция подсистем **СРО** (сметно-расчётный отдел) и **МТР** (материально-технические ресурсы).

---

## 🎯 О проекте

Аналитический контур, который объединяет данные двух подсистем и автоматически формирует **6 типов проектных документов** на основе единого источника данных. Цель — заменить ручной расчёт графиков, заявок и отчётов на воспроизводимый алгоритмический процесс.

### Что решает

- ❌ **Было:** графики и заявки считаются вручную в Excel; данные СРО и МТР живут в разных файлах; рассинхрон приводит к простоям и дефицитам на стройке.
- ✅ **Стало:** единый веб-контур, где аналитик вводит исходные данные → получает рассчитанные графики → выгружает готовый документ в нужном формате.

## 🛠 Стек

- **Next.js 15** (App Router) — серверные компоненты по умолчанию, маршрутизация на основе файловой системы
- **React 19** — UI-слой
- **TypeScript** — строгая типизация моделей задач и DTO документов
- **CSS Modules** — изолированные стили компонентов (замена scoped-стилей Vue), методология **BEM** для именования
- **Zustand** — стор для общих данных (исходные графики, справочники)
- **next/font** — оптимизированная подгрузка Inter Tight и JetBrains Mono

## 🚀 Запуск

```bash
# установка зависимостей
npm install

# dev-сервер с hot-reload (Turbopack)
npm run dev

# production-сборка
npm run build

# запуск production-сборки локально
npm run start

# проверка типов
npm run type-check

# линтер
npm run lint
```

После `npm run dev` приложение открывается на `http://localhost:3000`.

## 📂 Структура проекта

```
src/
├── app/                     роуты Next.js (App Router)
│   ├── layout.tsx           корневой layout — шрифты, провайдеры, Header
│   ├── page.tsx             /          — HomePage
│   ├── tasks/
│   │   ├── page.tsx         /tasks     — хаб задач
│   │   └── [id]/
│   │       └── page.tsx     /tasks/:id — страница задачи
│   ├── about/
│   │   └── page.tsx         /about     — о дипломе
│   ├── not-found.tsx        404
│   └── globals.css          подключение reset и tokens
├── components/
│   ├── atoms/               базовые элементы (Button, Field, Badge)
│   ├── molecules/           составные блоки (HomePageDescription, IntegrationScheme, TaskCard)
│   ├── organisms/           секции страниц (TopBar, TasksGrid, TaskFrame)
│   └── templates/           каркасы страниц (TaskPageTemplate с тремя зонами)
├── stores/                  zustand-сторы
├── models/                  TypeScript-типы предметной области
├── services/                расчётные алгоритмы задач (RCPSP и др.)
├── styles/
│   ├── tokens.css           CSS-переменные палитры
│   └── reset.css
└── lib/                     утилиты, хелперы
```

**Атомарный дизайн** (atoms → molecules → organisms → templates) выбран сознательно: пять из шести страниц задач используют один и тот же шаблон с тремя зонами, и переиспользуемость компонентов критична. Уровень `templates` отделяет вёрстку каркаса от данных, что упрощает разработку и потенциальное покрытие Storybook.

### Server vs Client Components

По умолчанию все компоненты в `app/` — серверные (рендерятся на сервере, не отправляют JS в браузер). Директива `"use client"` добавляется только там, где нужны хуки (`useState`, `useRouter`) или обработчики событий — преимущественно в формах ввода и интерактивных графиках.
